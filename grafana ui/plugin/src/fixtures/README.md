# Fixtures — data contract

Generated by `frontend/scripts/generate_fixtures.py` (deterministic, rerun-safe:
rerunning produces byte-identical files). `MockDataClient` reads these files
directly and maps them onto the domain types in `frontend/plugin/src/data/types.ts`.
**This file is the contract** between the generator and `MockDataClient` — if
a fixture's shape changes, update this doc in the same change.

Do not hand-edit any `*.json` file in this directory — regenerate it.

## The playback tape

All time-indexed fixtures (`nodeStates`, `telemetry`, `incidents`,
`predictions`, `events`, `flows`) are indexed against one shared **tape**:
`meta.json`'s `buckets` array, `bucketMs` (30000) apart, `bucketCount` long.
Bucket 0..49 = the real capture, chronological (already calm → incidents →
calm — buckets 0-1 and 29-49 are fault-free, 2-28 carry the real fault
episodes). Buckets 50+ = short synthetic episodes, one per fault type absent
from the real capture, each independently calm → fault → calm, appended in
alphabetical fault-type order. `windowBuckets` (50) is the sliding visible
window a consumer should trail behind the play-head cursor.

## `meta.json`

```
{
  bucketMs: number,              // 30000
  bucketCount: number,           // total tape length (real + synthetic episodes)
  windowBuckets: number,         // 50 — sliding visible window size
  startTsMs: number,             // epoch ms of bucket 0
  buckets: number[],             // epoch ms, one per bucket index, bucketMs apart
  deviceIds: string[],           // all 70 FRR (P/PE/CE) devices carrying metric state
  telemetryDeviceIds: string[],  // subset of deviceIds present in telemetry.json (see below)
  provenance: {
    spine: { kind: 'measured', file, bucketRange: [0,49], description },
    episodes: [ { faultType, scenarioId, bucketCount }, ... ],  // one per lifted synthetic episode
    episodeSource: { kind: 'simulated', file, description },
  },
}
```

## `topology.json` → `TopologyGraph`

All 148 nodes, derived from `topology-spec.yaml` knobs (not from any live
lab — `clab.yml` is not committed). `source: 'simulated'` for the whole
graph (not stamped per-node; the structure itself is derived, not measured).

```
{
  nodes: TopologyNode[],  // { id, role, siteType?, pop?, parent?, vrfs? }
  links: TopologyLink[],  // { source, target, kind: 'physical'|'tunnel' }
}
```

- `role`: `'p' | 'pe' | 'ce_branch' | 'ce_hub' | 'ce_dc' | 'host'` (24 + 12 + 24 + 6 + 4 + 78 = 148).
- `pop`: `'pop1'..'pop6'` on every node except hosts inherit their CE's POP; P/PE get it from the
  spec's POP structure, CE/host get the POP of the PE the CE round-robins onto.
- `parent`: set only on `host` nodes → their owning CE id.
- `vrfs`: set on CE nodes (all VRFs the site type gets) and host nodes (its single VRF).
- Links: physical = P-P intra/inter-POP mesh, P-PE (dual-homed), CE-PE, host-CE.
  Tunnel = WireGuard overlay: every branch/dc spoke ↔ every hub, plus adjacent hub-hub pairs.
  `sourceIf`/`targetIf` are omitted (not tracked at this fidelity).

## `nodeStates.json`

Per-bucket health for the 70 FRR devices only (hosts have no metric state,
consumer should render them as neutral/default). Buckets/devices with no
entry default to green — **only red/amber are emitted**.

```
{ [bucketIndex: string]: { [deviceId: string]: 'red' | 'amber' } }
```

- `red`: device has an active fault at that bucket (`is_fault` true and past its
  impact point, i.e. `time_to_impact_s <= 0`) OR an interface on it is oper-down
  (`if_oper_status == 2`).
- `amber`: device has a precursor at that bucket (`is_fault` true, `time_to_impact_s > 0`
  on at least one concurrent episode) and is not otherwise red.
- Computed via `export.precursor_mask`-equivalent logic across every row
  (`device`/`tunnel`/`interface` entity_type) for that device at that bucket.

## `telemetry.json` → `Record<deviceId, MetricSeries[]>`

**Down-selected** to keep the fixture compact (see `meta.json.telemetryDeviceIds`):
every device that appears in `incidents.json`, plus up to 2 baseline
("healthy") devices per role for topology click-through — 27 of the 70 FRR
devices, not all 70. Down-selected metrics too: only what's actually charted
per the plan (cpu/mem, interface rx/tx, errors/discards, queue, xcvr/env,
tunnel latency/jitter/loss). Dropped: `bgp_msg_*`, `rib_routes`,
`ospf_lsa_count`, `device_temp/power/fan/psu`, `tunnel_rekeys`.

Each device's array mixes:
- **Device-level** (`key: "<device>:<col>"`): `cpu_pct`, `mem_pct`. `source: 'measured'`.
- **Interface-level** (`key: "<device>:<entity>:<col>"`, one representative
  interface per device — lexicographically first): `if_in_octets`, `if_out_octets`
  (`source: 'measured'`), `if_in_errors`, `if_in_discards`, `if_out_errors`,
  `if_out_discards` (`source: 'measured'` — **`if_in_errors`/`if_in_discards`/
  `if_out_errors` are structurally always 0**, see `DATASETS.md` — never
  fabricated, kept honestly 0), `q_backlog_bytes`, `q_drops` (`source: 'measured'`),
  `xcvr_temp_c`, `xcvr_rx_power_dbm`, `xcvr_tx_bias_ma` (`source: 'modelled'`).
- **Tunnel-level**, only for devices with a WireGuard tunnel (CE hub/spoke;
  one representative tunnel per device): `tunnel_latency_ms`, `tunnel_jitter_ms`,
  `tunnel_loss_pct`. `source: 'simulated'`.

`MetricSeries.points` is one `{ tMs, value }` per tape bucket (`value: null`
where the row/entity doesn't exist at that bucket, e.g. no tunnel entity for
a P router); values rounded to 3 decimals.

## `incidents.json` → `Incident[]`

One per `scenario_id` across the whole tape (17 from the real capture + 11
from the lifted synthetic episodes = 28). `source: 'ground_truth'` (the fault
injection label is authoritative regardless of whether the underlying
telemetry for that episode is measured or simulated).

- `status` is always `'unknown'` in the fixture — **the consumer derives
  open/active/resolved at runtime from the play-head cursor** vs. the raw
  bucket fields below.
- `startedAt` / `impactAt` / `endedAt`: ISO timestamps from the tape's bucket
  clock (not the original real/synthetic wall-clock time).
- `startBucket` / `impactBucket` / `endBucket`: raw tape bucket indices — use
  these (not the ISO strings) to compute status against the cursor.
- `severity`: `SEVERITY_ORDINAL` (`export.py`) reverse-mapped to `low|medium|high`.
- `affectedScope`: deduped `"<device>:<entity>"` pairs touched by the episode
  (capped at 12).
- `evidence[]`: 1-3 items built from the row data (fault window, lead time if
  labelled, concurrent-episode count if `n_concurrent > 1`). `source: 'ground_truth'`.
- `rootCauseHypotheses[]` / `recommendedActions[]`: canned, per-fault-type text
  (21 fault types covered — see `ROOT_CAUSE_HYPOTHESES`/`RECOMMENDED_ACTIONS`
  in the generator script).

## `predictions.json` → `Prediction[]`

**Fabricated** (`source: 'mock'`), deterministic, designed to look like a
real model (~90% precision), not an oracle:

- For each of the 28 incidents: up to 4 prediction "ticks" firing on tape
  buckets before `impactBucket` (clamped to `startBucket`), `id` suffixed
  `-0..-3`. `confidence` ramps linearly 0.6 → 0.95 across the ticks;
  `timeToImpactSeconds` counts down to 0 at impact. Names the true
  `deviceId`/`faultType`.
- **1 seeded late call** (`id` suffixed `-late`): fires at/after the
  incident's own impact bucket (the longest incident, deterministically
  picked), lower confidence (0.55) — a miss that arrives too late to be useful.
- **1 seeded false alarm** (`id: 'pred-false-alarm-1'`): fires mid-tape on a
  device never involved in any incident, `confidence: 0.62`, and — by
  construction — no incident ever follows it.
- **69 total** predictions in the current tape (28 incidents × up to 4 ticks
  + 1 late + 1 false alarm).

`Prediction.timeToImpactSeconds`/`issuedAtMs` are the model's own output here
— never copied from the ground-truth `lead_time_s`/`time_to_impact_s` label
columns (those are used only to build `incidents.json`).

## `events.json` → `NetworkEvent[]`

Fabricated routing/syslog-style lines tied to each incident's fault type
(BGP ADJCHANGE, OSPF neighbor state, LDP session, SD-WAN tunnel/controller
lines, etc. — see `EVENT_TEMPLATES`), timestamped within the incident's
bucket window. `source: 'ground_truth'` for events tied to a real-capture
incident (bucket < 50), `'simulated'` for events tied to a lifted synthetic
episode.

## `flows.json` → `FlowRecord[]`

Sampled (every 5th tape bucket, to stay compact) from each telemetry device's
`entity_type=device` rows' `flow_bytes`/`flow_packets`. `source: 'measured'`.
No 5-tuple (`ipSrc`/`ipDst`/ports/`proto`) — those fields are omitted rather
than fabricated, since the underlying dataset only carries device-wide
aggregates, not real flow records.

## `conversations.json`

One seed `Conversation` per fault type present in `incidents.json` (21),
`id: "conv-seed-<faultType>"`. Each has a canned user message + assistant
reply pair in `messages[]`, plus a `seedResponse` field (shape =
`CopilotResponse`) a `MockDataClient` can serve when the copilot page opens a
conversation about that fault type. `source: 'mock'`.

`seedResponse.citations[]` always resolves to real files under `ragcorpus/`
— never a file that doesn't exist:
- fault types in the BGP/routing family (`bgp_flap`, `node_failure`,
  `rr_failure`, `bgp_cascade`, `controller_drift`, `ospf_area_flap`,
  `p_node_failure`, `ldp_session_flap`, `gray_failure`) cite
  `runbook-bgp-adjacency-down.md`.
- fault types in the tunnel/congestion family (`congestion`, `tunnel_degrade`,
  `asymmetric_loss`, `brownout`, `hub_spoke_congest`, `core_congestion`,
  `mpls_underlay_failure`, `path_asymmetry`, `srlg_cut`, `pop_isolation`,
  `core_partition`, `policy_drift`) cite `runbook-tunnel-latency-high.md`.
- every fault type also cites `topology-map.md` and `incident-template.md`.

## Regenerating

```bash
python3 frontend/scripts/generate_fixtures.py
```

Deterministic: reruns produce byte-identical files (verified via `diff -r`
in CI/manual QA). Total fixture size is a few MB (`telemetry.json` dominates
at ~4.7 MB; everything else is well under 100 KB each).
